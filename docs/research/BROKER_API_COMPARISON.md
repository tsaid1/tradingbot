# Broker API comparison: Interactive Brokers vs tastytrade

**Date:** 2026-11-05 · **Owner:** Agent B (research) · **Status:** DESK RESEARCH, PROOF-OF-CONCEPT NOT YET RUN
**Scope:** individual retail account held by a Middle-East resident (UAE or Saudi Arabia; spec decision D-03 must fix which), unattended bot that submits parsed signals with broker-native protective orders and no blind retries. Scored against the 100-point scorecard in spec section 11.3.

**Source access note.** All `interactivebrokers.com/docs/...`, `ibkr.info` and IBKR pricing/status pages return HTTP 403 to automated fetching. Quotes from those pages come from search-engine excerpts of the same URLs and are marked *(excerpt)*. Pages marked *(fetched)* were read in full. tastytrade's Salesforce help centre renders via JavaScript and could not be read; its Freshdesk mirror returned 404 on some articles. Claims re-verified verbatim by the reviewer on 2026-11-05 are marked *(re-verified)*.

## Executive verdict

1. **Proof-of-concept Interactive Brokers first**, via IB Gateway + TWS API. It is the only one of the two with (a) officially documented UAE eligibility, (b) documented partial-fill semantics for linked orders (OCA group rebalancing), (c) native trailing stops, stop and stop-limit, and GTC across stocks, options, futures and futures options, and (d) a server-side duplicate guard on the Web API (`cOID` must be unique for 24 h).
2. The IBKR POC must prove one thing above all: **unattended survival of the daily restart and the weekly 2FA re-login** with "Auto restart" on IB Gateway. If that fails the operational tolerance, IBKR is out regardless of score.
3. **Run a one-day tastytrade sandbox spike in parallel.** OAuth2 with a non-expiring refresh token and 15-minute access tokens is the cleanest unattended auth of the two, and OTOCO/OCO plus dry-run endpoints map directly onto the spec's risk-gateway rules.
4. tastytrade limits: no trailing stops in the API order-type enum, no stops on futures options, no GTC on futures (help centre), crypto disabled via API since 2026-06-29, **no deduplication of retried submissions** *(re-verified)*, and UAE/Saudi eligibility confirmed only by a third-party list.
5. **Score: IBKR 73/100, tastytrade 67/100** (acknowledgment/slippage criterion NOT MEASURED, provisional). Neither is disqualified for US equities/options. tastytrade is disqualified for any futures-options strategy that needs resting stops.
6. **Saxo OpenAPI is a credible third option** for a MENA individual (native related orders, token auth, individual OpenAPI access, $5,000 minimum) and should get a short spike if IBKR's auth burden proves unacceptable. Alpaca is not a fit for non-US individuals today.

## 1. API surfaces

**IBKR.** Three retail-relevant surfaces. (a) TWS API: socket connection to TWS or IB Gateway; each session accepts "up to 32 different client applications simultaneously" *(fetched: https://interactivebrokers.github.io/tws-api/connection.html, deprecated mirror of https://www.interactivebrokers.com/docs/tws-api/)*. (b) Web API: "The standard method of authenticating ... The Client Portal Gateway is a Java client that reverse-proxies authentication through SSO", listed for "Individual Accounts"; "OAuth 1.0a is the only supported authentication method for Third Party Developers" *(excerpt: https://www.interactivebrokers.com/docs/web-api/authentication/introduction.md)*. "Web API usage for individual clients involves an IBKR username and password" and "Clients with fully open and funded accounts may use our Web API ... without any onboarding or approval process" *(excerpt: https://www.interactivebrokers.com/docs/web-api/trading/getting-started/trading-access-for-individuals.md)*. IBKR is "merging our web-based API products into a single, comprehensive IBKR Web API" *(excerpt: https://www.interactivebrokers.com/campus/ibkr-api-page/webapi-doc/)*; the changelog runs to 2026-04-14 with no individual-OAuth entry *(excerpt: https://www.interactivebrokers.com/docs/web-api/changelog.md)*. (c) FIX via IB Gateway; not relevant for a retail bot.

**tastytrade.** One surface: Open API REST at `https://api.tastyworks.com` (sandbox `https://api.cert.tastyworks.com`), plus DXLink market-data websocket and account-streamer websocket; "You must have an OAuth client registered with tastytrade to use the API" *(fetched: https://developer.tastytrade.com/docs/get-started/ ; https://developer.tastytrade.com/docs/concepts/streaming/)*. Personal OAuth applications are created in my.tastytrade.com and "A personal OAuth application is restricted to your account only" *(re-verified: https://developer.tastytrade.com/docs/authentication/oauth2/)*. Whether international accounts can register OAuth apps: UNVERIFIED.

## 2. Authentication for unattended operation

**IBKR TWS/Gateway.** "enrollment in our SLS program is mandatory" *(excerpt: https://www.ibkr.info/article/1131)*. Daily and weekly cycle: "API users are advised to choose 'Auto restart' and 'Never lock Trader Workstation'"; "The weekly cycle starts on every Monday"; a "Soft token=0 received instead of expected permanent" failure means "you need to manually login again to complete the weekly reauthentication task" *(excerpt: https://www.interactivebrokers.com/docs/tws-api/doc/tws-settings/daily-weekly-reauthentication.md)*. Net: with Auto restart, expect one interactive 2FA per week plus a nightly restart; any crash mid-week requires a manual 2FA login. Forum reports of mid-day forced re-logins are anecdotal *(https://elitetrader.com/et/threads/questions-on-automating-ib.372642)*. Partial 2FA opt-outs carry restrictions per IBKR's KB *(excerpt: https://ibkb.interactivebrokers.com/node/2545)*.

**IBKR Web API.** Session "will timeout if no requests are received within a period of 5 minutes"; call `/tickle` "approximately every minute"; sessions last "up to 24 hours", resetting at local midnight *(excerpt: https://www.interactivebrokers.com/docs/web-api/authentication/faq.md)*. "Users must log in through the browser on the same machine as Client Portal Gateway" *(excerpt: https://www.interactivebrokers.com/campus/ibkr-api-page/web-api-staging/)*. OAuth 2.0 "is not available to Individual account structures"; offered to "licensed Organizations, Financial Advisors, and IBrokers" *(excerpt: https://www.interactivebrokers.com/docs/web-api/authentication/oauth-2/register.md ; page returns 403 to fetching, UNVERIFIED verbatim)*. Community reports that individual IBKR Pro accounts can self-register OAuth 1.0a keys are anecdotal and contradict the docs *(https://github.com/Voyz/ibind/wiki/OAuth-1.0a)*. Workarounds: IBC automates TWS/Gateway restarts *(https://github.com/IbcAlpha/IBC)*; IBeam automates the Client Portal Gateway but "doesn't have any method of automating the 2FA out of the box" *(https://github.com/Voyz/ibeam/wiki/Two-Factor-Authentication)*. Neither is IBKR-supported software.

**tastytrade.** "Access tokens are signed JWTs valid for 15 minutes"; "Refresh tokens are long-lived and do not expire"; "Refreshing does not rotate your refresh token"; "the legacy POST /sessions flow was decommissioned in 20260211" *(re-verified: https://developer.tastytrade.com/docs/authentication/oauth2/ ; https://developer.tastytrade.com/docs/release-notes/)*. A compromised refresh token is revoked by deleting the grant in my.tastytrade.com. No client-credentials grant is documented. Account authority levels `owner`, `trade-only`, `read-only` are returned by `GET /customers/me/accounts` *(fetched: https://developer.tastytrade.com/docs/concepts/accounts-and-customers/)*.

## 3. Order types and native protective or linked orders

**IBKR.** Bracket: children carry `parentId` = parent order id; parent and first child `transmit=false`, last child `transmit=true`, and "there is always a risk that at least one of the orders gets filled before the entire bracket is sent" *(fetched: https://interactivebrokers.github.io/tws-api/bracket_order.html ; current: https://www.interactivebrokers.com/docs/general/order-types/complex-orders/bracket-orders.md)*. OCA: ocaType 1 "Cancel all remaining orders with block", 2 "Remaining orders are proportionately reduced in size with block", 3 "... with no block"; "partial completion causes the group to re-balance" *(fetched: https://interactivebrokers.github.io/tws-api/oca.html)*. Order types by product via API: STP for CFD/BAG/CASH/FUT/FOP/OPT/STK; STP LMT, TRAIL, TRAIL LIMIT for CASH/FUT/FOP/OPT/STK; MIT/LIT; combos *(fetched: https://interactivebrokers.github.io/tws-api/basic_orders.html ; https://www.interactivebrokers.com/docs/general/order-types/trailing-stop-limit)*. Adaptive algo: `algoStrategy="Adaptive"`, `adaptivePriority` Urgent/Normal/Patient *(fetched: https://interactivebrokers.github.io/tws-api/ibalgos.html)*. Web API bracket: parent `cOID` reused as child `parentId`, submitted in one request to `/iserver/account/{accountId}/orders`; OCA via `"isSingleGroup": true` *(excerpt: https://www.interactivebrokers.com/docs/web-api/trading/orders/submitting-bracket-orders.md ; https://www.interactivebrokers.com/docs/web-api/v1/endpoints/orders/bracket-orders-oca-groups.md)*. **Partial fill of the parent: whether attached children are automatically resized is not stated in IBKR docs (UNVERIFIED; forum reports conflict).** GTC supported.

**tastytrade.** Order types `Limit, Market, Marketable Limit, Notional Market, Stop, Stop Limit`; TIF `Day, Ext, Ext Overnight, GTC, GTC Ext, GTC Ext Overnight, GTD, IOC` *(fetched: https://developer.tastytrade.com/reference/orders/postAccountsAccountNumberOrdersDryRun/)*. No trailing-stop value exists. Complex orders: OTO "when it fills, its orders (up to 3) are routed. They do not cancel one another"; OCO "when one fills the other is canceled"; OTOCO pairs "sit in Contingent status until the trigger fills, then route as OCOs"; PAIRS; "BLAST is deprecated" *(fetched: https://developer.tastytrade.com/docs/concepts/orders-and-order-types/ ; https://developer.tastytrade.com/reference/orders/postAccountsAccountNumberComplexOrders/)*. Legs: "Equity, future, and cryptocurrency orders are limited to 1 leg; equity-option and future-option orders allow up to 4 legs"; "Cryptocurrency trading is currently disabled through the API" (release note 2026-06-29). Partial fills: "tastytrade marks an order Filled as soon as possible, even if every individual fill is not yet processed ... re-fetch after a brief delay" *(fetched: https://developer.tastytrade.com/docs/concepts/order-lifecycle/)*. **How OTOCO children size after a partial trigger fill: not documented (UNVERIFIED).** Help-centre constraints *(excerpts, undated)*: stop-limit allowed on multi-leg option spreads, stop-market on spreads not, "stops on futures options" unavailable *(https://tastyworks.freshdesk.com/support/solutions/articles/43000697863-stop-orders-on-options-spreads)*; "GTC orders are not available for futures or options on futures orders" *(https://tastyworks.freshdesk.com/support/solutions/articles/43000541993-how-do-i-set-a-default-time-in-force-tif-)*; futures stop-market may not fill outside the protection price limit zone *(https://tastyworks.freshdesk.com/support/solutions/articles/43000435317-stop-orders)*.

## 4. Native preset support (spec risk R-16)

**IBKR.** "By default, TWS applies several precautionary settings ... customers will typically need to acknowledge a precautionary message and manually transmit the orders through TWS"; thresholds live under Global Configuration > Presets and "set a value to 0 to disable" *(excerpt: https://www.interactivebrokers.com/docs/tws-api/doc/orders/place-order/understanding-order-precautions.md)*. Global Configuration > API > Precautions offers "Bypass Order Precautions for API orders" plus narrower bypasses *(excerpt: https://www.interactivebrokers.com/docs/tws-api/doc/tws-settings/order-precautions.md ; field list https://www.interactivebrokers.com/docs/tws-api/protobuf/api-precautions-config.md)*. Precautionary settings enforce Percentage off market, Size Limit, Total Value Limit (default "100,000 USD"), Number of Ticks *(excerpt: https://www.interactivebrokers.co.uk/en/software/tws.bak/usersguidebook/configuretws/define_precautionary_settings.htm)*. **Net: presets act as a hold/prompt layer, not a hard reject, and there is no API to read or set them.** Order presets that auto-attach stop/target are TWS UI features and are not exposed to the API (UNVERIFIED negative). This confirms the spec's warning: a UI preset is not evidence that an API order carries protection.

**tastytrade.** No endpoint reads or writes risk presets. Readable: `GET /accounts/{n}/trading-status` (`options-level`, `is-futures-enabled`, `is-closing-only`) and `GET /margin/accounts/{n}/requirements` *(fetched: https://developer.tastytrade.com/docs/concepts/margin-and-risk/ ; https://developer.tastytrade.com/reference/account-status/getAccountsAccountNumberTradingStatus/)*.

**Conclusion for the risk gateway:** on both brokers, every protective order must be constructed and verified by our middleware; broker UI presets cannot be relied on. Spec section 10.1's "broker policy" layer reduces to account permissions and margin checks.

## 5. Dry-run, preflight and idempotency

**IBKR.** TWS `whatIf=true`: "instead of sending the order ... it will undergo a credit check"; result in `OrderState` with `initMarginBefore/After/Change` and `commissionAndFees` *(fetched: https://interactivebrokers.github.io/tws-api/margin.html)*. Web API `POST /iserver/account/{accountId}/orders/whatif` returns margin and commission; bracket supported *(excerpt: https://www.interactivebrokers.com/docs/web-api/api-reference/trading/trading-orders/preview-margin-impact.md)*. Idempotency: TWS orderId must be "greater than all previous order IDs"; error 103 "Duplicate order ID" *(fetched: https://interactivebrokers.github.io/tws-api/order_submission.html)*. Web API: `cOID` "must be unique within a 24-hour window", 64-char limit, not set on bracket children *(excerpt: https://www.interactivebrokers.com/docs/web-api/api-reference/trading/trading-orders/submit-new-order.md)*. A retried `placeOrder` with a new id is NOT deduplicated.

**tastytrade.** `POST /accounts/{n}/orders/dry-run` "Runs the full preflight checks for an order without routing it", returning `buying-power-effect`, `fee-calculation`, `warnings`; same for `/complex-orders/dry-run` *(fetched: reference pages above)*. Idempotency *(re-verified: https://developer.tastytrade.com/docs/guides/idempotency-and-retries/)*: "tastytrade does not provide a generic Idempotency-Key header, so safe retries are a client-side discipline"; "The API does not deduplicate retried submissions"; on timeout or 5xx "do not blindly resubmit", query `GET /accounts/{n}/orders` with a `start-date` on or before the submission day for the same `external-identifier`, and resubmit only if no match exists. The client-set field is `external-identifier`; `ext-client-order-id` is read-only on responses.

Both brokers therefore require the spec's submission journal and query-before-retry (NFR-01, Safety 3). IBKR's Web API `cOID` uniqueness is a helpful second guard; nothing else is.

## 6. Paper and sandbox

**IBKR.** Paper account requested in Client Portal, separate username/password, ready next business day if requested before 16:00 ET *(excerpt: https://www.interactivebrokers.com/campus/trading-lessons/request-paper-trading-account/)*. "the paper environment depends more on simulated technology"; fills simulated from top of book, no deep book; stops always simulated *(excerpt: https://www.interactivebrokers.com/docs/tws-api/doc/notes-limitations/limitations/paper-trading)*. Live subscriptions can be shared to paper, "up to 24 hours until the market data sharing takes effect", one active data session at a time; unsubscribed paper data is delayed *(fetched: https://interactivebrokers.github.io/tws-api/market_data.html)*. Same API, ports 7497/4002 by convention.

**tastytrade.** "Sandbox orders are routed to a market simulator, not to a real venue"; fills at rounded mid, larger orders partially fill "one tick worse per step"; IOC/FOK cancelled; scripted symbols (`NAT`, `TK`, `SWBI`, `ZZZZZ1`–`ZZZZZ11`) give deterministic reject/rest/fill/partial outcomes; "The environment resets every 24 hours"; `/market-data` returns 502; separate OAuth app *(fetched: https://developer.tastytrade.com/docs/sandbox/ ; https://developer.tastytrade.com/docs/faq/)*. The scripted partial-fill symbols are directly useful for spec tests T-07 and T-08.

## 8. Rate limits, streaming, reconciliation

**IBKR.** TWS API: limit is "half your maximum market data lines, per second" (50/s at 100 lines) *(excerpt: https://www.interactivebrokers.com/docs/tws-api/doc/pacing-limitations.md)*. Web API: "global request rate limit of 10 requests per second for each authenticated username"; `/iserver/account/orders` 1 req/5 s; 429 and a 10–15 minute penalty box *(excerpt: https://www.interactivebrokers.com/docs/web-api/trading/usage-and-availability/pacing-limitations.md)*. Streaming: TWS `orderStatus`, `execDetails`, `commissionReport`; "By default, only those executions occurring since midnight ... will be delivered" *(fetched: https://interactivebrokers.github.io/tws-api/executions_commissions.html)*; `reqOpenOrders` / `reqAllOpenOrders`, client id 0 binds manual orders *(fetched: https://interactivebrokers.github.io/tws-api/open_orders.html)*. **tastytrade.** REST "throttles by reasonable thresholds rather than a published per-endpoint quota"; "429 responses carry no rate-limit headers"; DXLink "5 concurrent sessions", "25,000 subscriptions per session", "10,000 subscription changes per minute"; failed-login IP block "about 8 hours" *(fetched: https://developer.tastytrade.com/docs/guides/rate-limits-and-backoff/)*. ## Disqualifier check (spec selection rule)

- **Eligibility:** IBKR UAE pass (official); IBKR Saudi pass-provisional (entity UNVERIFIED). tastytrade UAE/Saudi pass-provisional (third-party list only). No hard fail yet; both need written confirmation before funding.
- **Required protective-order semantics:** IBKR pass for STK/OPT/FUT/FOP. tastytrade pass for equities and single-leg or spread options (stop-limit); **FAIL for futures options needing stops and for futures needing GTC brackets.**
- **Non-reconcilable order outcome:** both pass (IBKR execution and trade history; tastytrade orders by date plus external-identifier). tastytrade's lack of dedupe is mitigated only by client discipline.

## Saxo OpenAPI and Alpaca for a Middle-East individual

**Saxo:** OpenAPI "is available for individual clients, institutional partners, and third parties" *(fetched: https://openapi.help.saxo/hc/en-us/articles/4488515250717)*; related take-profit and stop-loss orders are placed natively in the `Orders` array of `POST /trade/v2/orders` with OCO relations *(excerpt: https://saxobank.zendesk.com/hc/en-us/articles/4418479465361-How-do-I-place-related-orders-via-OpenAPI)*. MENA clients contract with Saxo Bank A/S via a UAE representative office; "$5000 required when opening an account" *(fetched: https://www.home.saxo/en-mena/accounts/individual)*. The spec already flags Saxo's 1 order/second throttle and related-order exclusions for some futures. Verdict: credible third option worth a short spike if IBKR's auth burden proves unacceptable.

**Alpaca:** individual non-US live trading is "invite-only beta" *(https://alpaca.markets/blog/non-us-live-trading-beta/)*; the country page only says to contact support *(fetched: https://alpaca.markets/support/countries-alpaca-is-available)*. Verdict: not a fit today.
